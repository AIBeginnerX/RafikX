# 디자인 게이트 체크리스트

trigger: UI·화면·컴포넌트·스타일 작업 시작 시.

## rules

- 기능 게이트 통과 + 디자인 게이트 통과 = 완료. 역도 성립한다.
- 코드 텍스트만 보고 "잘 만들어졌다" 판정 금지(NEVER) — 반드시 렌더링 산출물(스크린샷·실행 결과)을 생성해 검사.
- 색·간격·라운딩은 토큰으로만 — 하드코딩 값 금지.

## checklist

1. 타이포그래피 스케일 일관성 (정의된 크기 단계만 사용)
2. 간격 체계 — 4/8px 그리드 준수
3. 색 대비 WCAG AA 이상 (본문 4.5:1, 대형 텍스트 3:1)
4. 키보드 접근성·포커스 상태 표시
5. 반응형 브레이크포인트에서 레이아웃 붕괴 없음
6. 상태 완비성 — hover/active/disabled/loading/empty/error 각각 정의
7. 디자인 토큰 일관성
8. 모션은 절제 — 200ms 내외, 필수 피드백만

## good/bad

- good: `--space-2` 토큰 참조, 포커스 링 제공
- bad: `margin: 7px` 하드코딩, 포커스 스타일 제거( outline:none 에 대체 없음 )

## sources

- shadcn/ui — 구성·변형(variant) 패턴, 컴포넌트 합성 규칙
- Radix Primitives — 접근성·상태 설계 패턴
- Tailwind 공식 문서 — 디자인 토큰 체계
- 규칙 요약: RafikX 스킬 수확 파이프라인 (패턴 학습만, 코드 차용 없음)

## 렌더링 검증 절차 (S8 실행 방법)

- TUI (기본): tmux 로 실제 실행해 화면을 캡처해 판정한다 — 텍스트만 보고 통과 금지.

  ```sh
  tmux new-session -d -s render -x 120 -y 34 "<실행 명령>"
  sleep 3
  tmux capture-pane -t render -p            # 구조 확인
  tmux capture-pane -t render -e -p         # 색상 확인 (대비·하이라이트)
  ```

  체크: (1) 캡처 텍스트에 필수 요소가 보이는가 (2) -e 캡처에서 색 코드가 의도대로인가
  (3) 좁은 폭(예: 60x20)에서도 깨지지 않는가.

- 웹/이미지: 헤드리스 브라우저 스크린샷을 캡처해 대비·포커스 상태를 검사한다 (도구 있을 때).

- 판정 기록: 캡처물과 체크리스트 8항목 판정을 태스크 증거로 남긴다.
